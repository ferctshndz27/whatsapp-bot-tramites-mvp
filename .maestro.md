# Maestro Workflow Context
Generated: 2026-07-06

## Models & Providers
- Sin modelo de IA/LLM actualmente: el bot es 100% basado en reglas (máquina de
  estados con menús numerados), decisión deliberada para el MVP.
- A futuro se contempla incorporar Claude (aún no decidido cuándo ni cómo:
  API directa vs. framework).

## Workflow Architecture
- Flujo: mensaje de WhatsApp → webhook FastAPI (`app/webhook.py`, valida firma
  HMAC) → máquina de estados single-agent (`app/conversation.py`) → lista de
  respuestas de texto → envío vía Graph API (`app/whatsapp_client.py`).
- Single-agent hoy. Dividir en varios agentes (ej. uno de catálogo, otro de
  escalación) es una idea a futuro, condicionada a si se integra Claude —
  aún no se hará.
- Herramientas/funciones disponibles: `catalog.py` (búsqueda/paginación de
  servicios desde `catalog.json`), `whatsapp_client.py` (envío de mensajes),
  base SQLite (Client/Conversation/Message/Ticket) para persistencia y
  tracking.

## Quality & Evaluation
- Evaluación actual: pytest (15 tests — catálogo, conversación, firma HMAC
  del webhook). Es la única evaluación por ahora.
- Sin golden test cases todavía (transcripts reales de WhatsApp).
- Modos de falla: aún sin datos de producción; se documentarán según se
  detecten en el piloto.

## Constraints
- Costo: sin presupuesto definido todavía, pero está contemplado (Meta cobra
  por conversación pasado el tier gratuito; hosting/SQLite es ~$0).
- Latencia: unos segundos de demora es aceptable — deliberado, para no sonar
  demasiado robotizado/deshumanizado.
- Cumplimiento: sí aplica protección de datos personales (el bot referencia
  trámites que involucran actas, CURP, RFC de clientes).

## Priorities
Ranking (mayor a menor): Calidad > Seguridad > Velocidad > Costo.

humano, y tener tracking completo de cada proceso/solicitud.
